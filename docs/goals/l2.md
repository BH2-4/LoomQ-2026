## 目标定义（依据 problem_statement.md:206-214）

评测向 `agent_chat` 注入三类任务（**未公开的措辞变体**）：
1. **意图生成**（如"生成一个 3 比特 GHZ 态并全测量"）→ 回复须含可解析的 OpenQASM 2.0，模拟保真度 ≥0.97
2. **代码纠错**（prompt 带错误 QASM 并声明目标态）→ 修复产物须语义上实现目标态并通过保真度验证
3. **智能选后端**（如"15 比特、零排队"）→ 回复须含 `backend_capabilities.json` 中的规范标识原文（如 `braket_local_simulator`）

正式评测：12 个 case，每个 120 秒，**每个 case 必须至少一次有效模型调用**。

## 架构（ADR-3，必须遵守）

```
agent_chat(prompt)
  ├─ 1. 意图分类：生成 / 纠错 / 选后端 / 闲聊兜底
  ├─ 2a. 选后端 → 纯查表 starter_kit/backend_capabilities.json（不调 LLM 也可，但须保证至少一次模型调用的要求见"红线"）
  ├─ 2b. 生成/纠错 → 模板库（Bell/GHZ-n/Bell 变体/叠加态/简单算法…）+ LLM 只抽参数（JSON）
  ├─ 3. 本地验证：用 loomq 模拟器解析生成的 QASM 并模拟，分布/可解析性校验
  ├─ 4. 修复回路：失败时把具体错误回喂 LLM 重试（最多 2 次，预留 30-40s 预算）
  └─ 5. 兜底：降级到最近似模板（参数取默认）
```

## 红线（违反即翻车，逐条自查）

- 模型配置**只读环境变量** `LOOMQ_LLM_BASE_URL / API_KEY / MODEL / TIMEOUT_SECONDS`，不得硬编码任何 URL/Key/模型名
- 传输层复用 `starter_kit/llm_client.py`（零依赖 urllib，temperature=0，deepseek-v4-flash 自动附 thinking:disabled）
- LLM 输出解析**只用标准库** `json` + `re`；须容忍：空 content（DeepSeek 已知问题）、Markdown 围栏、JSON 截断——解析失败走修复回路，不许裸抛
- 每 case 120s 总预算：单次 LLM 调用设 `max_tokens` 防截断；整个流程在无 `LOOMQ_LLM_*` 环境时报错信息不得回显任何变量值
- Key 绝不进仓库、绝不进日志；提交前 `git diff` 自查
- 不动 `tests/`、`.github/`、`competition/`、`l2_policy.json`、`submission.yaml` 的既有字段（l2 参赛开关除外）
- 禁止关键词匹配式伪应答（反作弊条款会变体复测 + 代码审查）
